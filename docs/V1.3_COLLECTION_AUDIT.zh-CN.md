# CreatorScope V1.3 采集能力审计

审计日期：2026-11-21

项目：CreatorScope；分支：`main`
正式数据库：`instance/creatorscope_unified.sqlite3`；配置环境变量 `CREATORSCOPE_DB` 未设置，当前应用回退到该路径。

## 1. 审计结论

现有系统已经具备本地 SQLite、可见 Playwright 浏览器、有限批量采集任务、任务进度/暂停/恢复/停止、历史数据分析和导出。离线分析不依赖模型 Key 或 Agent。代码定义了从蒲公英创作者页取得详情、从可见复制链接进入小红书公开笔记页并读取内容/评论的流程。

**应用内的完整采集闭环尚未通过真实页面验收。** 当前正式库中的唯一应用内列表页样本只有粉丝数、日常阅读中位数、日常互动中位数和全部报价；没有新增创作者、笔记或评论。最近完整任务已停止，0 条记录、4 次创作者列表点击失败。Edge 页面清单中的蒲公英标签停在 `needLogout` 路由；CreatorScope 本地服务 `/api/health` 返回 `ok`，但 `/api/browser` 为关闭。V1.3 本次审计未发起采集、登录、验证码操作或数据库写入。

字段状态使用以下区分：**应用实采**=正式库存在 CreatorScope 当前运行任务写入的真实页面记录；**历史人工实测**=此前由人工配合可见浏览器取得，非当前应用批量任务成功；**仅解析器定义**=源码存在字段提取代码，但没有相应的应用真实采集记录；**受条件限制**=字段受登录、弹层、页面展示或媒体加载约束；**未测试**=没有足够证据判断。

## 2. 当前采集入口与运行环境

| 入口 | 当前行为 | 真实运行边界 |
|---|---|---|
| `POST /api/browser/open` | 打开独立的 headed Chromium persistent context；配置目录为 `%LOCALAPPDATA%/CreatorScope/pgy_browser_profile`。不复制 Edge 配置或注入 Cookie。 | 用户需在新窗口正常登录并停留在蒲公英页面。当前应用浏览器状态为关闭。 |
| `POST /api/browser/capture` | 读取当前蒲公英可见页，创建当前页快照任务。 | 正式库完成过 1 次真实列表样本写入，1 条记录、4 个指标；没有创建创作者详情或评论。 |
| `POST /api/tasks/collect-visible` | 在一个批次中按可选项遍历创作者、笔记和评论；任务设置上限为 10 位创作者、每人 3 篇笔记、每篇 20 条评论、总计 300 条评论。 | 当前只支持“蒲公英 → 可见复制链接 → 小红书公开页”的联动流程，不是独立的小红书搜索采集器。评论选项会隐含启用笔记遍历。 |
| `POST /api/tasks/<id>/pause\|resume\|stop`；`GET /api/tasks` | 控制任务并查看进度、访问计数、失败位置和原因。重启时运行中的可见采集改为暂停，可由界面恢复检查点。 | 恢复是从现有检查点继续；没有独立的失败笔记队列或“只重试选中失败项”入口。 |
| `POST /api/tasks/import-baseline`、`POST /api/tasks/import-file` | 导入本地历史基线或 JSON/CSV。 | 属于本地数据入口，不是实时网页采集。 |
| 首页、评论、分析和导出接口 | 读取本地 SQLite，提供过滤、统计、图表及 CSV/JSON/JSONL。 | 不要求登录或模型 API Key；本地 ECharts 资源在仓库内。新闻 RSS 只有用户主动点击采集才访问网络。 |

采集实现位于 `creatorscope/browser.py`、`tasks.py`、`ingest.py`、`db.py` 和 `creatorscope/__init__.py`。前端采集设置和任务控制位于 `templates/index.html` 与 `static/js/app.js`。`run.ps1` 默认检查 Python、数据库完整性并在 `127.0.0.1:8765` 启动应用。

## 6. 任务控制与稳定性审计

**可复用：** 单线程任务队列和单线程浏览器控制器；headed persistent context；页面域名限制；手动登录暂停；验证码/安全验证暂停；手机号提示只通过唯一可见关闭控件处理；批次内写入与检查点；评论同批去重；来源与时间保留；用户可暂停、恢复、停止；失败原因显示在任务列表。

**需要修复：**

1. `_capture_list_row()` 按固定单元格索引读取四项数值，不取创作者名称或公开平台 ID；无法以当前入口独立补齐创作者实体资料。
2. 任一笔记阶段异常目前记录失败后抛出 `PauseForUser`，会暂停整个创作者批次；这与“单篇失败不影响其他笔记”不符。
3. 恢复使用单个 `creator_index/note_index` 检查点；没有独立失败队列、逐条重试选择、按字段缺失补采或任务操作日志表。`result_json.failures` 只是有限的任务 JSON 记录。
4. 正式 schema 只有指标 `parse_status`，没有统一的 `captured/not_displayed/not_loaded/access_denied/parse_failed/not_attempted/not_applicable` 字段状态，也没有每批字段覆盖/失败/重复质量报告。
5. 列表行、详情 tab、笔记卡、复制链接及小红书正文/评论使用固定文本/CSS 选择器。页面结构变化会造成超时；必须提供安全的失败分类，不能用强制点击穿透遮罩恢复。
6. 手动当前页捕获要求现有浏览器会话已打开，并且当前页属于蒲公英域名；UI 支持启动浏览器和任务创建，但当前应用独立浏览器与用户现有 Edge 标签不是同一登录会话。

## 7. 复用与改造范围建议

- **复用：** `PgyVisibleBrowser` 的可见操作、安全暂停、URL 校验、显式复制链接流程；`TaskManager` 的持久检查点、进度、暂停/恢复/停止；`ingest_payload()` 和 `ingest_comment_snapshots()` 的原始值、来源、批次、采集时间及幂等写入；当前来源感知分析、导出和本地 ECharts 页面。
- **改造：** 将创作者资料、笔记快照、评论采集拆成可独立选择且共享同一批次/来源/断点机制的阶段；在当前可见 DOM 有证据时提取名称和公开平台 ID；将单笔记失败写入失败队列并继续后续笔记；增加对失败项的显式重试；将字段状态、质量统计写入可追溯本地记录。
- **课堂运行：** 当前 Flask/SQLite/本地静态资源已可在无模型 Key 下启动并分析正式本地历史数据。应保留该路径作为无需登录的离线演示，并增加清楚的演示启动方式和独立真实数据副本；不得用模拟数据替代历史记录。
