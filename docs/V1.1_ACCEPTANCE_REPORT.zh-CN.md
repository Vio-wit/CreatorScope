## 1. 架构与运行环境

- Windows 本地应用，Python 3.11 虚拟环境、Flask、Playwright headed persistent context、SQLite、pandas/NumPy、jieba、WordCloud、ECharts。
- 入口为 `run.ps1`；本地服务绑定 `127.0.0.1:8765`，浏览器访问 `http://127.0.0.1:8765`。
- 正式数据库为 `instance\creatorscope_unified.sqlite3`。本轮真实采集和数据分析使用该统一库；恢复演练只在 `_preview\` 下的副本执行。
- 页面可见采集由 CreatorScope 任务管理器调用独立浏览器配置。蒲公英数据只能从可见蒲公英页面取得；小红书笔记地址必须由蒲公英页面的可见复制链接操作提供。未调用非公开接口、未读取 Cookie/Session、未绕过登录或验证。

## 2. 采集流程与字段

目标流程是：CreatorScope 页面创建任务 → 可见浏览器读取蒲公英列表和创作者页面 → 从笔记详情复制真实链接 → 顺序打开小红书公开笔记页 → 提取正文、话题及可见评论 → 分批写入 SQLite 并更新断点、任务状态 → 看板与导出读取同一批次。

代码支持读取页面实际可见的创作者基本资料、粉丝数、地域/类目、报价、日常阅读和互动中位数；笔记标题、发布时间、曝光/阅读/互动/关注指标、视频时长；公开笔记正文、话题及可见评论层级、显示时间、点赞/回复原始值和置顶状态。缺失值保留缺失状态；`10+` 不会被转成精确整数；评论指纹按批次和笔记作用域生成。

这些是采集器实现目标和合成测试范围，不等于本轮均已通过真实网站验证。真实页面样本和字段覆盖见第 4 节。

## 3. 数据库设计与安全

统一库含 creators、notes、batches、records、metric_values、comment_snapshots、tasks 等表，以及兼容查询视图。每条 record 新增可空 `source` 字段，schema 从 v1 增量迁移到 v2；历史数据通过批次来源回退，不重建数据库、不覆盖旧批次。`metric_snapshots` 和分析/导出均优先使用记录级来源。

采集到的创作者/作者名称、平台 ID、笔记 ID、来源链接、正文、评论原文及其他公开可见字段以原值保存在记录或源行 JSON 中；标准化值另存于指标表。系统内部仍使用数据库主键和哈希索引做关联/去重，这些内部值不替代原始字段。上传密码、Cookie、Session、Token、Authorization 和 API Key 等认证凭据会被排除。旧版 `pgy_live_sample_2026-11-19.json` 未包含原始身份字段，无法从其哈希恢复；只从保留的原始研究来源回填可恢复字段。
