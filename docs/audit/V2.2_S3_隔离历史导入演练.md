# V2.2 S3：隔离历史证据导入演练

核验日期：2026-11-23。基于 `main` 的 V2.1 S1/S2 审计及 S3 导入代码，使用单独的本地 SQLite 证据库，不连接远程服务器，不写正式应用库，不修改历史原始文件。源文件可能含个人信息或带参数的链接；原始文本、隔离数据库、质量 JSON 和备份均不应提交到 Git。

## 功能与操作

`creatorscope/history_evidence.py` 为独立命令入口。它只允许创建新的隔离库或写入带有专用标记的既有隔离证据库，拒绝写入没有标记的现有数据库；不调用会覆盖应用 `creators` 的原有导入逻辑，也未改变应用数据库 schema。

```powershell
# 将路径替换成已有目录下的隔离库和实际来源文件；不使用正式库路径。
.\.venv\Scripts\python.exe -m creatorscope.history_evidence --db <隔离库路径> import <来源文件> --name <来源名称>
.\.venv\Scripts\python.exe -m creatorscope.history_evidence --db <隔离库路径> import <索引文件> --name <来源名称> --identity-index-only
.\.venv\Scripts\python.exe -m creatorscope.history_evidence --db <隔离库路径> report
.\.venv\Scripts\python.exe -m creatorscope.history_evidence --db <隔离库路径> list-records <source_id>
.\.venv\Scripts\python.exe -m creatorscope.history_evidence --db <隔离库路径> trace <record_id>
```

支持 UTF-8 CSV、JSON、JSONL 和本次笔记 TXT；CSV 按原文件起始行号追溯，JSON 数组按从 1 开始的序号追溯，JSONL 按行号追溯。来源以 SHA-256 去重，保留各个来源路径及导入运行记录；相同记录内容出现在不同文件时保留来源记录并标记内容重复。`report` 提供来源、哈希、时间、行数、异常、重复运行、身份结果、每来源字段覆盖、缺失及冲突；`list-records` 提供记录 ID，`trace` 才按需输出该记录的原始字段、声明、指标和索引候选。`trace` 的输出可能包含敏感原文，不应复制到公开位置。

身份标识按平台和类型分别保存，小红书主页 ID、公开账号、蒲公英 ID 不互换。相同平台及类型的强标识一致时可关联并保留别名；同名不同 ID 不自动合并；无 ID 建立待核验身份；明确冲突时原始记录与身份声明保留在独立冲突记录，既有标识不覆盖。`identified` 仅表示有可用标识，不代表经人工或平台确认；索引候选仅供查询，不自动并入身份。

字段证据保存原值、候选解析值、单位、统计周期、解析状态及映射版本；`--`、空字符串、JSON `null` 和 `0` 区分处理。列表起价与一口价分开；价格没有明确币种符号时单位留空。仅字段专属周期字段可用于该字段，文件名、更新时间、导入时间均不冒充原始采集时间。TXT 完整原文留存；正文和话题只在可识别边界内生成 **candidate**，不是已完成清洗或人工核对的正文。

## 重复、原始值和恢复验证

- 在最终隔离库中，同一 MUSINSA 文件再次导入及另一同 SHA-256 文件导入均识别为重复，各报告 291 条重复，未重复写入来源记录；两个真实路径均保留。
- 逐行比较 EPT 36 行、MUSINSA 291 行和评论 7 行的原字段与导入记录，全部一致；10 份详情 JSON 的对象及 20 份笔记 TXT 原文逐个对照一致。演练使用的 35 个实际来源路径在导入后重新计算 SHA-256，均与库内来源指纹一致。
- 10,111 条记录没有可证明的采集时间，保留 `NULL`；EPT 的原始采集时间与导入时间分开。没有把文件修改时间、数据更新日期或当前时间写作未知采集时间。
- 将最终隔离库备份到 `_backup/v22_s3_history_with_comments_20261123.sqlite3`，再恢复到 `_preview/v22_s3_restore_check_20261123.sqlite3`；`PRAGMA integrity_check` 为 `ok`，来源、路径、记录、身份、声明及字段证据表的行数与原库一致。恢复副本仅用于演练，未覆盖任何既有库。
- 自动化专项测试覆盖同文件/同内容重复、同名不同 ID、同 ID 别名、缺 ID、身份冲突、起价与一口价、`--`/0/NULL、单位与字段周期、未知时间、原始字段追溯、JSONL 异常及隔离库恢复。真实数据未出现的冲突和异常以合成测试为证。
- 最终全量 `unittest discover -s tests`：92 项通过。此前一次全量运行中已有的 `test_waiting_for_manual_close_can_be_stopped` 等待超时；单独重跑所在的 24 项采集测试通过，随后全量重跑 92 项通过。该偶发超时未定位根因，不表示相关风险已消除。

## 未完成事项与下一步

- 当前交付是独立隔离证据库和命令行管理，不是前端导入界面，也没有把历史身份或指标写入现有达人库。与已有应用达人之间的关联、确认流程、正式库迁移、统一分析数据集及看板尚未实现。
- 笔记正文和话题是边界提取候选，仍需抽样人工核对并过滤页面噪声；未找到边界的原文仍保留，不能称为已成功清洗。评论专题属于独立数据源，尚不能证明可关联到当前达人。
- 不同来源的报价币种、起价/一口价和指标周期未核实；禁止按当前解析值直接跨来源汇总。S4 应先构建带来源、时间、身份可信度及有效样本量的分析视图，再决定哪些字段进入图表。
