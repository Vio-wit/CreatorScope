# CreatorScope V2.4：历史达人资源扩充与课堂展示

记录日期：2026-11-23。开发基线为 `main`，HEAD `f2555d7`。本计划承接 V2.3 页面收敛工作，目标是让本地 rednote 历史资料成为可搜索、可筛选、可分析和可展示的达人数据成果。

## 目标与呈现原则

- 把更多已有历史达人资料纳入 CreatorScope 的隔离历史证据库，减少重复采集。
- 达人库突出名称、平台标识和实际可用字段；名称相同但没有相同强标识的资料仍分别保留。
- 展示来源记录数、可识别身份数和有效字段样本数；不把不同文件行数相加称为去重达人总数。
- EPT、MUSINSA、历史索引、详情资料等可以同时进入达人资源库。分析指标仍按来源和可比较口径分组，避免把统计周期或单位不同的数字混成一个统计结果。
- 原文件只读保留；原始字段、来源路径、文件哈希、行号和可证采集时间都可追溯。未知时间留空。
- 笔记正文、标题、话题分开展示。原文保留，页面分析使用可识别的正文/话题候选，不把正文里的 `[话题]` 说明标记当成高频主题。
- 产品主要导航围绕“达人库、数据分析、智能筛选与采集”；来源路径、批次等细项放在搜索结果详情或二级筛选中，避免首页控件拥挤。

## 开发阶段

### S1：新增隔离历史数据集

1. 保留已存在的 S3 最终库和全部备份；新建带隔离库标记的 V2.4 历史库，不对现有库进行就地扩写。
2. 使用现有来源哈希、行号和身份声明机制，导入上述首批资产；同一文件重复运行保持幂等。
3. 对 9,790 行主索引正常创建可见资料；旧索引亦作为独立来源导入。强标识完全相同时才建立关联，无 ID 的名称仍可在列表出现。
4. 输出来源数量、行数、错误数、重复数、身份关联情况、字段覆盖率、笔记正文/话题解析情况。未识别字段或原值一律保留。

验收：新库 `integrity_check=ok`；核心来源导入完整；原始文件哈希前后不变；重复导入不增加来源记录；正式数据库和原 S3 库不变。

### S2：历史达人库扩大展示

1. 增加“全部历史达人”视图，默认按粉丝数、名称排序，支持关键词、平台 ID、领域、地域及有值数值字段筛选。
2. 用强标识合并重复来源记录的展示身份，并保留别名、来源数和每条原始记录详情；无强标识资料各自展示，不按姓名自动合并。
3. 允许资料缺粉丝、领域或互动字段；仅在字段有有效值时参与对应筛选和图表。
4. 详情展示原值、标准化值、来源文件/行号、可证时间与统计口径。

验收：搜索结果可以展开详情并追溯源文件；同名不同标识仍分别显示；空值不变为 0；历史浏览接口只读。

### S3：分析看板与课堂内容

1. 全量展示有数据支撑的粉丝分布、日常阅读、日常互动、领域、地域和单篇笔记互动情况。
2. EPT、MUSINSA 及其他周期/单位不同的来源分别统计；报价起价与一口价分列，跨来源口径不一致时仅展示覆盖情况。
3. 每个统计显示有效样本数、数据来源、时间及字段口径。残缺字段也进入覆盖分布，不补造缺失值。
4. 增加笔记正文/话题的可读样本列表和高频词分析；保留少量人工可读课堂样本，另外显示已解析文本数量与可用字段覆盖。

验收：图表与列表行数可对账；样本数只按有效值计算；正文标记及页面导航词不挤占话题词频；原文仍可追溯。

### S4：界面收敛与实际验收

1. 统一三个主要入口，减少“更多工具”中的一级项目；保留报告、评论、新闻、质量等旧路由并移入相关模块或次级入口。
2. 统一数据筛选区，首页只保留常用条件；来源、批次和内容类型移入折叠筛选或详情。
3. 实测正式达人库与历史达人库搜索、筛选、详情、分析图表和笔记内容；核对页面没有重复卡片、字段标签噪声或溢出。
4. 记录自动化测试、浏览器验证、正式库与历史库哈希及实际导入数量。

验收：旧页面可访问；新增历史库只读接口与隔离数据库对账；实际浏览器展示来源范围和有效样本数。

## 实施顺序与提交

先完成本计划及 S1 隔离批量导入工具，再完成 S2 历史达人库视图，接着做 S3 内容与统计展示，最后整理导航并验收。每阶段先运行适当检查、核对将提交的具体文件，再按已授权范围提交到 `main`；不推送，不修改正式数据库，不清理任何未跟踪文件。
