# CreatorScope V2.3：产品界面收敛与课堂展示优化计划

基线：`main`，提交 `d8a4764`（V2.2 S4 历史只读分析视图）。本文件记录 V2.3 的开发范围、实施顺序和验收口径。V2.3 延续 S4 的只读历史证据边界，并加入课堂展示采集成果与字段覆盖分布的目标。

## 当前实现进度

截至 2026-11-23，已开始第一轮开发：主导航收敛为达人库、数据分析、智能筛选与采集；报告页改用共享侧栏；正式库达人列表补充名称/ID 搜索；S4 历史证据增加独立只读候选列表和按粉丝、日常阅读、日常互动筛选；历史分析增加字段取得率、解析成功率和字段覆盖档位看板。历史候选没有自动合并，页面不显示身份核验状态。

字段覆盖看板按 S4 三个来源组当前追踪的 15 个字段展示。只读计算得到：EPT 36 条记录，字段档位为 80% 及以上 10 个、60% 至低于 80% 0 个、低于 60% 3 个、未验证 2 个；MUSINSA 291 条记录，分别为 3、2、0、10 个；达人详情 10 条记录，分别为 10、0、0、5 个。覆盖率按取得原值数计算，保留原值但解析失败的字段计入取得率，单独计入解析失败数；页面显示无值、空白/NULL、未读取到也分别计数。

本轮尚未完成首页所有重复区域的整理、历史来源与正式库的可切换整合、历史达人对比、自然语言筛选和整条课堂流程的浏览器验收。上面列出的字段档位是当前 S3 隔离库样本统计，不代表去重达人数量或长期采集稳定性。

## 一、产品目标

把 CreatorScope 整理成面向课程演示的达人数据工具，围绕“达人库、数据分析、智能筛选与采集”组织页面，演示从发现候选达人到查看数据和执行采集的完整过程。

不以图表数量或字段齐全作为目标。真实取得的部分字段也可展示和分析；页面应同时呈现有效样本数和字段覆盖情况，让数据成果可见。缺失值保留为空，不用 0 填充。

## 二、当前已存在的能力

- 首页包含采集任务、统一数据总览、图表、S4 历史分析、达人库、创作者对比、笔记管理和笔记对比等区域。
- 共享侧栏已有达人库、数据分析、AI 辅助、采集任务入口；报告页仍保留旧侧栏。
- 正式库已有达人列表、关键词和部分字段筛选、排序，以及限定同一批次的 2 至 4 人比较；尚无完整的达人增删改查流程。
- S4 历史数据通过只读接口独立读取 EPT、MUSINSA 和达人详情样本。三组共 337 条来源记录，不等于 337 位去重达人；当前历史接口不提供稳定的达人名称和身份关联投影。
- 现有 AI 页面可以预览和执行模型分析，但还没有“自然语言需求 → 可编辑条件 → 本地候选筛选”的完整流程。AI 接口目前基于正式库数据。
- 可见采集任务已有进度和暂停相关流程；五人课堂演示继续复用现有采集代码。
- S4 字段表只覆盖五个主要数值字段。历史证据库已有原始值、文本值、解析数值、单位、周期及解析状态，可用于扩展字段成果看板。

## 三、开发阶段

### S1：页面与导航收敛

**工作**

1. 整理全部页面区域、导航链接和 `static/js/app.js` 初始化依赖。
2. 将主要导航归为“达人库”“数据分析”“智能筛选与采集”三个入口。
3. 将笔记管理、评论分析、数据质量、新闻和实训报告放入“更多工具”，保留现有路由和功能。
4. 让报告页也使用共享侧栏，清理重复导航。
5. 检查首页重复的概览卡片和图表说明，只移除重复展示，不删除现有数据能力。

**验收**

- 三个主要入口清楚可见；所有原有工具页面仍能打开。
- 首页各锚点可正确跳转；窗口刷新后入口状态与当前页面一致。
- 页面拆分或区域移动后，页面脚本不会因元素缺失而停止初始化。

**主要文件**：`templates/_sidebar.html`、`templates/index.html`、`templates/report.html`、`static/js/app.js`、`static/css/app.css`。

### S2：达人资源视图

**工作**

1. 补上正式库达人关键词搜索入口，整理现有领域、地域、粉丝范围、报价范围和排序控件。
2. 为 S4 历史证据提供只读候选列表投影，明确数据集、来源记录引用和实际可读字段；在历史数据集内支持列表、关键词搜索、可用字段筛选和详情查看。
3. 同名记录先独立展示，不自动合并；有冲突时保留原始名称与 ID。没有可靠值的字段显示空。
4. 记录完整增删改查的接口和隔离数据库需求。若实现正式库写操作，先设计并验证备份、恢复和隔离迁移。

**验收**

- 正式库和各历史数据集可以选择、搜索并查看详情。
- 历史列表显示来源记录数量，不把来源行数表述为去重达人数量。
- 历史只读查询不改变正式库、S3 证据库和原始文件。

**主要文件**：`creatorscope/analytics.py`、`creatorscope/history_analytics.py`、`creatorscope/__init__.py`、`templates/index.html`、`static/js/app.js`。

### S3：分析看板与采集成果覆盖

**工作**

1. 保留覆盖较高且口径明确的粉丝、日常阅读和日常互动作为主要图表。
2. 将其他有部分有效值的字段纳入补充表格或图表；每项标注有效样本数、总样本数、单位、统计口径及来源。
3. 新增“采集成果与字段覆盖”看板，按当前选定数据集展示原值取得率、字段覆盖档位分布和采集成果概览。
4. 原值覆盖率使用“读到非空字段值的记录数 / 当前数据集记录数”；格式解析失败但已保留原值的记录仍计入原值覆盖。课堂展示档位为：80% 及以上、60% 至低于 80%、低于 60%、未验证。档位仅用于展示当前样本完成度，不宣称长期稳定。
5. 单独显示解析成功率，计算口径为“成功解析的数值或文本记录数 / 已读到原值的记录数”。另行区分页面显示 `--`、页面空白/NULL、程序未读到字段、解析失败和其他解析状态。数值 `0` 是有效值；不能把页面上的 `--` 当成解析失败或数值 0。
6. 可用于定量比较的字段须有兼容单位和统计口径。其他字段仍显示原始值及采集情况，不强行合并不同单位、周期或报价含义。
7. 继续按 EPT、MUSINSA、详情样本分开分析；若用户明确需要总体成果概览，记录数可以作为采集工作量相加展示，但必须标为来源记录总数，不能称为去重达人总数。

**验收**

- 可切换数据集；字段覆盖数量、百分比和档位合计与该数据集实际字段证据一致。
- 有效、页面空值、未读到、仅文本、解析失败状态能分别展示。
- 部分有效字段可进入图表或明细，不因缺失排除整条来源记录。
- 图表显示有效样本数；缺失值留空；0 按有效值处理。
- S4 的三篇笔记继续作为课堂案例；若扩展样本，先人工抽查正文边界及话题。

**主要文件**：`creatorscope/history_analytics.py`、`creatorscope/history_evidence.py`（仅在确有缺陷或缺少状态证据时审慎调整）、`templates/index.html`、`static/js/app.js`、`static/css/app.css`。

### S4：自然语言智能筛选

**工作**

1. 定义允许的筛选字段、运算符和值格式，首批使用已有的关键词、领域、地域、粉丝范围，以及其他通过字段覆盖审查的兼容字段。
2. 自然语言输入经 AI 转为结构化条件后，在界面展示供用户编辑。
3. 服务端只接受白名单字段，校验范围和值，再执行本地筛选。
4. 无 API Key、模型失败或用户关闭 AI 时保留手工筛选；模型外发沿用现有预览和确认流程。
5. 结果支持打开达人详情、选择比较和返回编辑条件。历史数据的筛选只能在具备可靠字段投影的数据集内执行。

**验收**

- 完成“描述需求 → 得到可编辑筛选条件 → 本地匹配 → 查看候选人”的流程。
- 非白名单字段、错误类型和越界条件会被拒绝或要求修改。
- 无 AI 配置时，手工筛选和对比可继续工作。

### S5：达人比较与合作建议

**工作**

1. 将现有正式库同批次 2 至 4 人对比入口整理到达人库和分析页中。
2. 为同一历史数据集内的 2 至 4 条记录提供粉丝、日常阅读和日常互动对比。
3. 每项指标按共同有效样本或逐项有效样本说明范围；不兼容报价暂不进行跨来源比较。
4. AI 合作建议只基于当前可用的候选字段和比较结果，并展示实际输入依据。

**验收**

- 正式库比较仍遵守同一批次约束；历史比较不跨数据集。
- 图表和建议能对应到页面展示的数据，缺失指标不补 0。

### S6：课堂演示与交付验收

**工作**

1. 编写短演示顺序：达人库 → 智能筛选 → 候选比较 → 数据分析与字段覆盖 → 五人可见采集。
2. 复用现有独立浏览器、任务进度、暂停和手动处理流程，不增加长期无人值守调度。
3. 用隔离测试数据检查 UI 与数据联动；真实平台部分只记录当场实际结果。
4. 实际检查单图 PNG 导出；批量 PNG、打印/PDF 等其他导出需求另行验收。

**验收**

- 演示中的加载、采集进度和结果来自实际任务状态，不用动画伪造成功。
- 记录实际验证内容、未验证事项、提交号和数据库保护结果。

## 四、实施约束

- 先确认当前分支和工作区；保留所有未跟踪文件、研究资料、备份、浏览器证据和数据库旁文件。
- S4 历史证据层保持只读；不覆盖或删除历史原始资料。
- 不因身份不完整或笔记、评论字段缺失而隐藏其余已取得数据；身份匹配状态留在内部数据管理层，不作为课堂主界面的警示内容。
- 不把来源记录行数直接称为去重达人总数；来源分组和字段口径在图表及详情中可查看。
- 不把未解析的页面文本作为结构化数值；原始文本可以用于内容示例或覆盖展示。
- 每一阶段完成后记录实际结果并提交；不推送。

## 五、推荐开发顺序

依次完成 S1 导航与页面整理、S2 达人资源视图、S3 分析和覆盖看板、S4 智能筛选、S5 对比建议、S6 演示验收。每阶段只修改达成本阶段验收所需的文件，发现 S3 导入机制的实际缺陷时才回到导入层修复。

S4 基线说明见 [V2.2 S4 历史只读分析视图](V2.2_S4_历史只读分析视图.md)。

- 正式达人搜索：搜索 `Winnie维尼` 后得到 4 条匹配记录。
- 历史候选库：EPT 粉丝范围 150 万至 160 万筛得 2 条，名称搜索 `愚蠢小刘` 返回 1 条并可展开 13 个字段；MUSINSA 范围 90 万至 92 万筛得 1 条，名称搜索 `魔女教主娜娜` 返回 1 条并可展开 5 个字段；达人详情范围 40 万至 45 万筛得 1 条，名称搜索 `恩真Blaga` 返回 1 条并可展开 10 个字段。数据集切换后仍按来源独立查询，没有身份合并。
- 数据核对：直接只读 SQL 与分析 API 对账，EPT 36 行、MUSINSA 291 行、达人详情 10 行；字段覆盖分布分别为 `10/0/3/2`、`3/2/0/10`、`10/0/0/5`（高/部分/低/未验证）。关键有效数分别为粉丝 `36/278/10`、日常阅读与互动 `33/221/9`。MUSINSA 的获赞收藏、发布笔记数及领域没有映射；报价字段语义不一致，暂不跨来源比较。
- 布局：宽屏浏览器截图（1792×893）中主要图表正常绘制，未见横向溢出；较窄的嵌入式显示曾出现横向滚动和内容拥挤，窄屏断点仍需单独复测。首页同时存在“统一数据总览”和筛选范围数据概览，指标不同但可在下一轮统一命名和层级。未读取浏览器控制台，因此不作“控制台零错误”结论。

## 七、第二轮开发准备

1. 完成首页与分析页层级收敛：明确全局实体总览、筛选范围统计、历史来源分析三者的区别，减少重复说明；在 768–900 像素等窄屏宽度复测导航、筛选器、图表与表格横向溢出。
2. 统一正式达人库与历史候选库的切换入口，但保持来源隔离和历史只读，不自动合并身份；切换时保留各数据集自己的搜索条件和结果数。
3. 完善历史详情的来源行号、原始字段和指标口径展示，并增加同一数据集内 2–4 条记录的比较；缺失值保持空值，逐指标显示有效样本数。
4. 整理粉丝分布、日常阅读与互动核心图表，标题与说明标出来源、单位、周期及有效样本；报价在含义统一前只展示原值和覆盖，不跨来源排序或比较。
5. 自然语言筛选第一版采用以下数据白名单与边界：
   - 所有历史来源可筛选名称/账号文本、粉丝数（人）；粉丝有效数 EPT `36/36`、MUSINSA `278/291`、达人详情 `10/10`。
   - 日常阅读与互动仅按各自来源筛选，允许缺失并排除空值；有效数 EPT `33/36`、MUSINSA `221/291`、达人详情 `9/10`。历史字段 `period` 未单独记录，跨来源比较前需核实统计周期。
   - 地域作为来源内文本筛选；领域只对 EPT 与达人详情开放，MUSINSA 没有该字段。
   - 获赞收藏与发布笔记数只对 EPT 和达人详情开放；MUSINSA 不纳入。报价由于起价、一口价和原始报价语义不同，暂不进入通用数值筛选白名单。
   - 数值条件使用有限的 `>=`、`<=`、区间；字符串仅支持名称、账号、领域、地域的包含匹配。服务端按选定来源校验字段，不把缺失值当作 0，也不跨来源混算。

第一轮为只读历史分析与界面可用性验收；五人实时采集、浏览器控制台、窄屏完整适配、导出按钮下载以及真实平台流程未在本轮验证。
