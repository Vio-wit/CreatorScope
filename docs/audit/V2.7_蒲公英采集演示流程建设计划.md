# CreatorScope V2.7：蒲公英采集演示流程建设计划

记录日期：2026-11-24。规划基线：分支 `v2.6-frontend-visual`，HEAD `dc56975`。本文只记录需求、现状核查、差距与实施方案，**本轮不执行任何代码改动**；是否实施、按哪个阶段实施，另行授权。本计划承接 V2.6 前端视觉优化，不改变已收敛的三页信息架构、数据口径与采集落库行为。

## 一、目标与范围

### 1.1 演示视频要呈现的操作流程

本次建设面向一段「数据采集」演示录屏，前端需要支持人工按以下三步点击走通：

1. **打开蒲公英页面**：在工作台点击按钮打开独立浏览器，进入蒲公英登录页；若隔离配置里已保留登录态，则直接到达已登录的达人列表页。
2. **人工筛选后确认执行采集**：操作者在蒲公英页面上用平台自带筛选条件得到目标达人列表，回到工作台向程序确认当前列表，设置采集范围后启动采集。
3. **遇阻碍时人工介入后继续**：采集过程中若出现验证码、安全验证、登录弹窗、遮罩弹窗等阻碍，前端明确提示操作者去浏览器处理；处理完成后任务继续采集。

### 1.2 结论先行

**可以做，采集器底座已经具备，不需要重写。** 现后端采集器、任务队列、断点续采、阻碍检测、前端入口与结果展示均已落地；距演示流程的差距集中在三处演示友好度：

- 启动前缺少「当前列表识别预览」的核对步骤；
- 阻碍发生时的前端提示不够突出、未按阻碍类型分类给指引；
- 演示模式与可采集模式的切换、登录态保留需要一套固定的录屏前准备流程。

### 1.3 范围边界

| 层 | 纳入范围 | 不纳入 |
| --- | --- | --- |
| 后端采集器 | 复用现有 Playwright 采集流程、阻碍检测、断点与状态机；仅在需要预览/状态回显时补只读接口 | 新增爬虫式批量抓取、绕过登录或风控、自动填验证码 |
| 前端工作台 | 采集确认步骤、当前列表预览、阻碍提示横幅与引导文案、状态展示 | 改动达人库/笔记分析/AI 对比等既有页面口径 |
| 数据 | 复用主库 `instance/creatorscope_unified.sqlite3`；小样本采集 | 大规模全量爬取、批量评论或私信动作 |
| 合规 | 只读取蒲公英域名与小红书公开页可见字段，不发表评论、不改动账号资料 | 任何模拟登录态破解、cookie 共享方案 |

## 二、现状核查（只读对照代码）

### 2.1 现有采集链路

后端 `creatorscope/browser.py` + `creatorscope/tasks.py` 已实现一条可见浏览器采集链路：

- 目标域名：`pgy.xiaohongshu.com`，起始页 `/solar/pre-trade/note/kol`（博主广场）。
- 流程：达人列表行 → 博主详情页 `blogger-detail` → 笔记面板 → 复制笔记链接打开小红书公开笔记页 → 抓正文/指标/评论。
- 浏览器：Playwright Chromium `launch_persistent_context`，有头窗口、隔离配置目录，登录态随配置目录保留。
- 任务队列：单线程 `ThreadPoolExecutor`，任务落库，支持排队/运行/暂停/停止/完成/失败状态与断点续采。

### 2.5 阻碍检测与处理机制（现状）

现有代码把阻碍分成两类，对应两种处理节奏：

**A. 可关闭遮罩类 —— 自动等待人工关闭后续采（状态 `waiting_user`）**

抛 `ManualDismissRequired`，任务置 `waiting_user`，后端轮询等待，操作者在浏览器关掉遮罩后自动继续，无需回前端点按钮。已覆盖：

- `overlay`：蒲公英弹窗遮挡采集区域（点击行被模态拦截）；
- `note_panel`：笔记详情面板无法安全自动关闭；
- `phone_login`：小红书侧手机号登录提示弹窗。

**B. 需要实质处理类 —— 暂停，人工处理后回前端恢复（状态 `paused`）**

抛 `PauseForUser`，任务置 `paused` 并保留断点；操作者在浏览器完成验证/登录/调整筛选后，需回工作台点「从断点恢复」。已覆盖的触发词与场景：

- 安全验证、访问异常、请完成验证、人机验证、滑动验证、拖动滑块、操作频繁、账号异常；
- 蒲公英未登录（请先登录 / 登录后查看 / 账号登录）；
- 列表为空、无匹配结果；
- 断点创作者身份无效、存在多个博主广场标签页、身份无法唯一匹配；
- 小红书笔记内容要求登录才能查看；
- 等待关闭弹窗期间浏览器被关闭。

任务状态文案（前端现状）：排队中、处理中 `progress%`、等待你关闭弹窗、已暂停、正在停止、已停止、已完成、失败。

## 三、对照演示三步的差距清单

### 3.1 步骤一：打开登录页 / 已登录页面

**已具备**

- 「打开蒲公英浏览器」按钮启动有头隔离窗口，直达达人列表起始 URL；配置目录持久化，上次登录态有效时免登。
- 状态提示区分：已在蒲公英域名 / 在其他域名 / 浏览器未打开三态。

**差距**

1. **登录态有效性未预检**：前端只判断域名是否为 `pgy.xiaohongshu.com`，不判断是否仍处于登录态；是否被要求登录要等到采集跑起来、`_check_page_blocker` 命中后才暴露。演示前没有一个明确的「当前是否已登录」指示。
2. **页面角色引导偏弱**：起始页是登录页还是达人列表、当前是博主广场还是博主详情，仅以小字状态提示呈现；录屏时操作者不易一句话讲清当前所处环节。
3. **配置目录占用风险无前置提示**：隔离配置被其他浏览器进程占用时，启动失败信息在任务结果里才出现，打开按钮阶段没有预警。

### 3.2 步骤二：人工筛选后确认执行采集

**已具备**

- 采集类型勾选、人数/笔记数/评论数设置、启动按钮齐备；程序读取的是当前页面可见列表行，与平台人工筛选结果对齐。
- 后端校验：可见列表人数少于目标人数时暂停并提示，不会自动缩小目标。

**差距**

1. **缺启动前列表预览**：当前没有「当前列表识别到几位、分别是谁」的只读预览；操作者在启动前无法核对筛选结果与即将采集对象是否一致，演示中缺少一个「确认当前列表」的动作落点。
2. **筛选条件不回显**：平台侧选了哪些领域/地域/粉丝区间，程序不读取也不展示；讲解时只能口头说明，工作台看不到本次采集对应的筛选快照。
3. **启动为一步直达**：填完参数点「启动可见采集」即提交任务，没有二次确认或「先预览再启动」的分段节奏；对演示视频而言，确认环节偏轻。

### 3.3 步骤三：遇阻碍人工介入后继续

**已具备**

- 遮罩类阻碍进入 `waiting_user`，后台自动轮询，关掉即续采；验证/登录/空列表类进入 `paused`，断点保留、可恢复；失败笔记可单独重试。
- 失败明细按「创作者序号 / 笔记序号 / 原因 / 尝试次数」记录，可展开查看。

**差距**

1. **暂停提示不够突出**：`waiting_user` 与 `paused` 的引导目前只落在任务卡片状态行；演示时操作者视线若在浏览器侧，容易错过工作台提示。缺少置顶横幅或强提示把「现在需要你做什么」顶到页面上方。
2. **阻碍类型未分类指引**：现有文案偏笼统（「页面要求验证码或安全验证」「请正常流程处理」），没有按「关闭弹窗 / 完成滑块验证 / 重新登录 / 调整筛选条件 / 检查网络」给出对应下一步动作。
3. **两套恢复节奏在 UI 上未区分**：遮罩类是自动等待续采，验证/登录类需要手动恢复；前端没有把「正在等你关弹窗（无需点按钮）」和「请处理完后点恢复」两种状态在视觉上明确区分。
4. **暂停时浏览器侧指引不同步**：任务暂停后，顶部浏览器状态提示条仍只反映域名/页面类型，不会带上当前阻碍的处理建议。

### 3.4 演示工程层面

- 当前演示服务以 `DEMO_MODE=1` + 只读演示库启动，采集按钮隐藏、写接口返 409；正式录屏前必须切换到非演示模式、指向可写主库并重启服务。
- 隔离浏览器登录态有有效期，距离上次采集（2026-11-21）已过数日，cookie 大概率过期，需在录屏前重新登录一次并确认保留。
- 主库留有两批历史暂停批次（卡在安全验证），录屏前需决定续跑还是废弃新建，避免演示时翻到旧暂停任务。

## 四、分期建设方案

### 阶段 A：录屏前准备（零代码，先做）

目标：在不改代码的前提下，把演示环境备到可一键走流程。

1. 用主库、非演示模式启动工作台（不设 `CREATORSCOPE_DEMO_MODE`，`CREATORSCOPE_DB` 指向 `instance/creatorscope_unified.sqlite3`，端口 8765）。
2. 打开隔离浏览器，完成蒲公英登录，确认能稳定进入达人列表且不弹验证；让登录态写入配置目录。
3. 在蒲公英页面按演示口径筛好一组小样本列表（建议 2–3 位创作者、每人 1–2 篇、评论 0–10 条），确认列表行可被表头识别。
4. 清理或标注主库两批历史暂停批次，决定本次录屏用新建批次。
5. 按本计划附录的录屏走查清单预演一遍，记录卡点。

**产出**：一套可复现的录屏前启动步骤（环境变量、浏览器登录、样本口径、批次处置），附在演示指南文档中。

### 阶段 B：启动前列表预览与确认（P1，前端为主，补只读接口）

目标：把「人工筛选 → 程序确认当前列表 → 启动」做成清晰的两步。

1. 新增只读预览能力：后端提供当前浏览器可见达人列表的轻量快照（识别人数、前 N 位名称/ID、列表是否为空、是否处于登录页），不写入数据库；前端在采集设置区上方显示「当前列表：N 位，前几位为 …」。
2. 预览状态与启动按钮联动：列表为 0、未登录、不在蒲公英域名时，启动按钮保持禁用并给出对应原因。
3. 启动前二次确认：点击启动后先展示本次口径（人数/笔记/评论/三类勾选），确认后再提交 `collect-visible`。
4. 设置区补步骤引导文案：先在蒲公英页面筛选 → 回工作台核对列表预览 → 设置范围 → 启动采集。

**边界**：预览只读取当前可见 DOM 行，不滚动翻页、不展开详情；平台原生筛选条件的回显若拿不到，不在本期硬造。

### 阶段 C：阻碍提示强化与分类指引（P1）

目标：阻碍发生时，操作者一眼看到「现在要我做什么、要不要回前端点按钮」。

1. 任务状态置顶横幅：当前任务处于 `waiting_user` / `paused` / `failed` 时，在采集工作台顶部显示对应横幅，内容为阻碍摘要 + 下一步动作。
2. 阻碍类型到指引文案的映射：
   - 遮罩/弹窗/笔记面板 → 「请在浏览器关闭弹窗，关闭后自动继续，无需点按钮」；
   - 滑块/人机验证/操作频繁 → 「请在浏览器完成验证，完成后回工作台点恢复」；
   - 未登录/登录过期 → 「请在浏览器重新登录蒲公英，登录后点恢复」；
   - 列表为空/无匹配 → 「请在蒲公英调整筛选条件，再点恢复」；
   - 浏览器被关闭 → 「重新打开浏览器后恢复任务」。
3. 区分两种恢复节奏：横幅上明确标注「自动等待中」还是「需手动恢复」，并在需要时把「从断点恢复」按钮放进横幅操作区。
4. 浏览器状态提示条同步带上当前阻碍建议，与任务横幅口径一致。

**边界**：不自动关闭验证、不自动登录；所有验证与登录动作仍由人工完成。

### 阶段 D：演示收尾与录屏清单（P2）

目标：采集完成后顺畅过渡到成果展示，并沉淀一份可复用的走查脚本。

1. 采集完成后提供跳转入口：达人库清单、笔记案例与正文、评论分析、导出 JSON/CSV/指标文件，对应既有页面与导出接口。
2. 沉淀录屏走查清单：环境启动 → 登录态确认 → 筛选与预览 → 启动采集 → 阻碍处理预案 → 成果查看与导出 → 异常回退（停止任务/新建批次/查看失败明细）。
3. 记录常见踩坑：配置目录被占用、登录态过期、风控验证、列表重排导致身份对不上、评论达到 300 上限。

## 五、验收标准

### 5.1 流程走查（非演示模式、主库）

1. 点击「打开蒲公英浏览器」能弹出隔离窗口；已登录时直达达人列表，未登录时停在登录页，状态提示与实际一致。
2. 在蒲公英完成筛选后，工作台预览显示的人数与名单和当前列表一致；列表为空或未登录时启动按钮禁用并说明原因。
3. 确认口径后启动采集，任务进入排队/运行，进度、访问数、新增数、重复数在任务记录中实时更新。
4. 人为触发弹窗类阻碍时，任务进入 `waiting_user`，横幅提示「关闭弹窗后自动继续」；关闭遮罩后任务无需手动点按钮即继续。
5. 人为触发验证/登录类阻碍时，任务进入 `paused`，横幅按类型给出处理指引；浏览器完成处理后点「从断点恢复」，任务从断点继续。
6. 采集完成后可从工作台跳转查看达人、笔记、评论成果并导出；失败笔记可单独重试。
7. 全流程无控制台报错；115 项既有单元测试保持全绿；新增预览/提示逻辑补对应测试。

### 5.2 不破坏既有口径

- 不改动达人库、笔记分析、AI 对比的数据口径与字段映射。
- 不扩大采集上限（人数 10、笔记 3、评论 20、总评论 300 保持不变）。
- 演示模式下只读约束保持有效，写接口仍返 409。

## 六、风险与踩坑记录

| 风险 | 说明 | 应对 |

| 风控/安全验证 | 短时间高频访问易触发滑块或「操作频繁」，历史上两批采集卡在此处 | 演示用小样本、降低频率；验证类暂停保留断点，处理后恢复 |
| 登录态过期 | 隔离配置 cookie 有有效期，过期后详情页要求登录 | 录屏前重新登录确认；未登录阻碍有明确暂停指引 |
| 配置目录占用 | 隔离 profile 被其他 Chromium 进程锁定会启动失败 | 阶段 A 先关闭占用进程；启动失败提示中补充关闭占用的建议 |
| 列表重排 | 批量采集期间达人列表排序变化，可能导致身份对不上行 | 现有断点保存创作者身份，打开前二次解析匹配；匹配不上则暂停并提示新建批次 |
| 演示模式误启 | 以 `DEMO_MODE=1` 启动会隐藏采集按钮、写接口 409 | 录屏前按阶段 A 的环境变量清单核对模式 |
| 旧暂停批次干扰 | 主库留有历史 `paused` 批次，演示时可能被翻到 | 阶段 A 明确续跑或废弃；演示脚本优先定位本次新批次 |
| 公开笔记受限 | 部分小红书笔记要求登录或仅粉丝可见，拿不到正文 | 该篇记为失败并记录原因，不影响其他笔记；失败明细可重试 |
