# CreatorScope V2.5：统一达人库与课程展示开发计划

记录日期：2026-11-23。规划基线：`main`，HEAD `66b22ee`。本文先记录需求与实施方案，后续实施进度见第九节。本计划承接 [V2.4 历史资源扩充计划](V2.4_历史达人资源扩充与课堂展示计划.md)，与 V2.4 的页面或排序方案不一致时，以本文为准。

## 一、目标与范围

CreatorScope 面向数据采集与处理课程，展示从真实数据采集、清洗、筛选、统计到达人合作决策辅助的过程。分析优先使用现有采集器已实现相应采集逻辑的字段；历史 rednote 资料可以复用，但须区分历史资料和本项目实际采集批次，不将历史数据称为本次五人任务的新采集成果。

界面收敛为三个真正切换的主页面：**达人库、数据分析、智能选人与采集**。只保留一个达人库；达人横向对比放入智能选人与 AI 分析流程。

本阶段**暂不考虑**长期趋势、跨批次趋势、评论情感、评论主题、达人间评论对比。实训报告和新闻关联退出产品页面规划。暂缓或移除入口不等于删除已有代码、历史数据、备份或未跟踪文件；未经专门授权不删除。

## 二、已知事实与问题

1. 截至当前基线，三个主入口是同一长页面的锚点，并非真正独立页面。正式库与历史库各有列表和分析接口。
2. 截图中的“抓绒图案连帽衫-灰色”等记录是 MUSINSA 商品，被历史索引误标成达人；`16825067` 等原始数字被当作粉丝数，现按粉丝降序排序将其排到前面。两份索引中至少有 171 条和 9 条来源记录明确包含商品链接；这不是去重商品数，也不是污染总量。V2.4 报告中的 17,652 条是受污染的展示条目数，**不能作为有效达人人数**。
3. 五人真实采集批次为 `3a70fbec3f714bada4b4fc6f1c5dc6b3`，位于 `_preview/v2_field_validation_20261123.sqlite3`，并未自动进入当前空主库的 8767 演示实例。五位各有列表、详情、内容表现和粉丝分析记录；本批未开启笔记正文、话题与评论采集。
4. 现有采集器能读取受众性别、年龄、地域、设备和兴趣摘要；五人各为 5/5 文本，但完整分类比例是否可通过页面正常交互取得，尚未验证。不可将摘要补成完整分布。
5. 列表地域提取曾出现误读，详情地域至少一条误取人设；历史字段 `region`、`ip_location` 等语义不同。只有确认是页面账号 IP 的值才能计入“蒲公英账号 IP 属地”。
6. V2.4 隔离历史库中 26 条结构化笔记有 24 条非空话题为 Python 列表字符串，当前历史笔记接口不能正确展示该格式；2 条为 `[]`。现有 1,933 条话题候选数主要来自 TXT，不代表这 24 条已正确解析。

## 四、统一达人库规则

### 4.1 先排除商品和非达人

1. 盘点各来源字段、来源类型和 URL。明确为商品详情、商品 SKU 或其他非达人的记录，从达人列表、达人计数、分析图表和导出中排除；原始记录和来源文件不修改、不删除。
2. 以可信来源和链接类型识别，覆盖截图中的 `musinsa.com/products/6257477`、`/products/6257544` 等实际例子；不只靠名称关键词或粉丝数阈值判断。
3. 没有 ID 但有合理达人来源、名称或其他达人证据的记录可以保留为独立资料；无法判断的记录暂不当作已确认达人参与统计，原文仍可追溯。不得因为缺少非核心字段拒绝真正的达人资料。
4. 重新输出来源行数、识别出的非达人记录数、可展示达人条目数及未判定记录数；这些数字各有分母，不冒称全部已去重人数。

### 4.2 同一列表及排序

在统一列表中依次展示：

1. **之后新采集的达人**：按实际采集时间倒序。区分真实采集任务与文件导入；未知时间不伪造。
2. **上述五人批次**：按有效字段完整度从高到低。
3. **之前的历史资料**：按有效字段完整度从高到低。

五人不另建页面或单独表格。实施前核对已有正式库批次，明确哪些是之后的新采集，不能把旧批次或历史导入自动当作新采集。

完整度按一组固定、可解释的达人字段计算：名称、平台 ID、粉丝数、日常阅读、日常互动、获赞收藏、发布笔记数、图文/视频报价、领域、已确认的账号 IP 信息等。逐字段只计一次：有效文本和成功解析数字计入，真实 `0` 有效；空值、`--`、未读取、失败、明显错误不计入。报价类型分别保留，不能把原文和数值各算一个字段。明确字段权重或采用等权计数，实施后写入字段说明；缺字段不丢弃达人。

同一平台、同一类型的强 ID 一致时，可在展示层关联；ID 明确冲突或只有同名时不自动合并，无 ID 资料保持独立。跨组同一达人显示一行，位置按最高优先组；各次采集快照和原始值可追溯。对整套结果先做类型过滤、身份关联、搜索筛选和排序，再分页；同分以名称和稳定记录 ID 作确定性排序。

### 4.3 展示字段

列表优先展示名称、粉丝数、日常阅读、日常互动、报价、领域及已确认的账号 IP；其余字段、来源、采集时间和原始值在达人详情中查看。无值显示“—”，不填 0。搜索支持名称和平台 ID；常用筛选保持简洁，其余放“更多条件”。

## 五、三页布局与功能取舍

### 5.1 达人库

- 单一达人表、搜索和筛选；不再展示独立历史达人表。
- 按第四节的三组优先级排序；达人详情展示可用字段及资料来源。
- 从列表选择达人进入智能选人与对比。不能让统一页仅改变视觉而继续漏掉历史资料。

### 5.2 数据分析

- 默认展示粉丝规模分布、日常阅读与互动、采集成果与字段覆盖；每图显示来源范围、有效样本数、必要的单位与周期。
- 在同页提供笔记内容入口：列表、正文/话题搜索、少量可读案例与词频；有同口径单篇互动时可显示一张小样本辅助图。
- 创作者领域作为辅助筛选/统计；报价原值、起价及图文/视频一口价分列。币种、单位和周期未证实时不混合画价格关系图。
- “蒲公英账号 IP 属地”仅使用来源明确、抽样确认是账号 IP 且成功提取的字段；历史单写地域而语义不明的记录保留原文，不进入 IP 统计。账号 IP 不是创作者真实属地；粉丝地域画像也不与账号 IP 混算。
- 字段覆盖图保留完整、部分、缺失等分布；按需展开逐字段原值、解析成功、页面无值、未读取和失败明细。五人采集质量与历史资料覆盖分开标明范围。
- 相关性只作为同来源、同语义、同周期共同有效数据的探索性结果；展示样本数，不解释为因果。代码现有最低 3 条只是计算下限，不是可靠性保证。
- 长期及跨批次趋势、评论情感与主题、达人间评论对比本阶段不展示、不扩展。实训报告和新闻关联不放入产品导航或本轮开发范围。

### 5.3 智能选人与采集

- 采集入口保留独立浏览器、登录、筛选、选择创作者/笔记/评论、五人课堂演示、实时状态、日志及需人工处理提示；不增加长期无人值守架构。
- 智能选人接统一达人库：自然语言需求转为可编辑筛选条件并执行搜索；无 AI 或 API Key 时仍可使用普通筛选和已有采集、分析功能。若现有实现未支持，明确列为开发任务，不宣称已完成。
- 达人横向对比集中在此：选 2–4 人，先展示粉丝、日常阅读、互动等并列数据和简单柱图；仅共同可比值进入同一图，缺失保留为空。AI 合作建议为可选操作，依据实际数据、可见缺失、来源和时间生成，不补造数值。
- 原有 AI 对比目前依赖正式库及指定批次；接入统一达人结果需要修改数据契约，并保留旧采集、报告等接口兼容性。实训报告虽然退出页面规划，已有代码和文件继续保留。

## 六、受众画像验证计划

当前五人仅验证了五类摘要文本，不能承诺完整比例。后续在正常登录、用户允许的可见页面操作下：

1. 选择一位达人，等待粉丝分析区域本身加载；按需正常滚动和悬停，检查页面可见内容、图表标签和可读取元素。
2. 分别记录性别、年龄、粉丝地域、设备、兴趣：页面展示的类别与数值、程序取到的类别与数值、来源及可证周期；区分页面未展示与程序未读取。
3. 仅对能实际读取并核对一致的类别保存结构化值；保留原文。页面没有给出的比例不推算，不使用绕过验证或非公开接口。
4. 如果一人验证可行，再以五位达人扩验；按字段统计取得数、页面无值、读取失败和解析成功率。课堂级样本不宣称长期稳定。
5. 验证前，单达人详情显示原始画像摘要；只有获得可信的结构化分布时才启用对应图表或同口径对比。验证受平台登录、页面加载与安全验证影响，必要时暂停提示人工处理。

## 八、数据保护、测试与提交

- 优先使用现有 `_preview` 隔离数据库进行投影和测试；不得向正式达人库导入未经确认的历史数据，不直接修改既有历史证据库。若今后确需修改正式库，先备份并验证恢复方案。
- 保留全部原始历史资产、研究材料、备份、数据库及其旁文件和全部未跟踪文件；不清理目录、不访问远程 IMOK 生产资产。
- 测试应包括真实商品链接、低于十亿的误填粉丝、无 ID 达人、字段缺失和真实 0、同名不同 ID、同 ID 跨来源、五人批次与新采集优先级、未知时间、排序后分页、IP 与粉丝地域区分、话题列表解析和未配置 AI 等。
- 完成各独立阶段后运行适当自动化检查并实际浏览器验收相关页面；清楚区分旧记录、隔离测试和当前真实结果。按会话中已授权范围只暂存相关代码/测试/文档，分阶段提交 `main`，不推送。
- 当前计划不保证所有历史资产都适合统计，也不保证所有画像字段都能通过页面自动化获取；以真实验证和字段口径为准。

## 九、实施记录

### S1：数据范围修正（2026-11-24）

- 已在只读隔离历史库 `_preview/v24_history_expanded_final_20261123.sqlite3` 中核对：180 条来源记录的 `xhs_profile_url` 明确指向 `musinsa.com/products/...`。原始证据未修改；历史达人来源计数、达人列表、分析记录与字段覆盖分母现在都会排除这些商品记录。
- 排除后，“全部历史达人”范围为 18,297 条来源记录、17,472 条可展示条目；它们是来源记录/关联展示数，不是经人工去重确认的人数。达人列表前五条不再出现商品记录，商品误填的粉丝数也不进入排序或统计。
- 历史笔记话题解析现兼容 JSON 数组、Python 列表文本及带井号话题；历史笔记接口从原来 1,933 条带话题记录提升到 1,957 条，标题 2,109 条、正文 2,016 条。原始证据库保持只读。
- 定向自动化测试 9 项通过，Python 编译检查通过。浏览器验收和全量回归测试安排在后续阶段完成。

### S2：统一只读达人投影（2026-11-24）

- 新增统一只读列表接口，读取正式 CreatorScope 库、隔离五人批次和 V2.4 历史证据库；所有来源都以 SQLite `mode=ro` 打开，按文件及 WAL 状态缓存列表快照，不写入三套数据库。
- 当前接口复核实数为：基线后新采集 0 条、五人课堂采集 5 条、既有采集与历史资料 17,487 条，共 17,492 条展示条目。它们是只读投影中的展示条目，不是跨库人工去重人数；此前记录的 17,514 条与当前接口结果不一致，以本次实际接口响应为准，具体来源构成仍以接口返回的来源快照为准。
- 顺序按计划执行：基线之后的新采集按时间倒序、五人批次按 11 项字段完整度、既有资料按字段完整度排序。不同数据源名称相同不会合并；不同系统的平台 ID 类型含义不明确时不跨系统自动关联。商品链接继续在各历史数据视图中排除。
- 统一接口支持来源分组、关键词、领域、账号 IP 属地、粉丝范围和分页。旧接口仍保留供现有页面兼容。29 项统一库、历史分析、既有分析和数据库回归测试通过；三套真实隔离/本地数据库读取前后哈希一致。
- 当前列表排序已按字段存在性计算完整度；历史报价仍保留来源原值，尚未因币种和起价口径不明而混入统一报价筛选或价格比较。

### S3：统一页面与主入口收敛（2026-11-24）
