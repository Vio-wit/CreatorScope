# CreatorScope V2.6：前端视觉美术优化计划

记录日期：2026-11-24。规划基线：`main`，HEAD `9f7de82`。本文只记录需求、现状与实施方案，**本轮不执行任何代码改动**；后续是否实施、按哪个阶段实施，另行授权。本计划承接 [V2.5 统一达人库与课程展示开发计划](V2.5_统一达人库与课程展示开发计划.md)，不改变 V2.5 已收敛的三页信息架构与数据口径。

## 一、目标与范围

### 1.1 目标

在不改动业务逻辑、数据契约、后端接口、采集与清洗行为的前提下，统一前端视觉语言：

1. 把分散的颜色、字号、间距、圆角、阴影收敛为一套可复用的设计令牌。
2. 统一按钮、卡片、表格、表单、徽章、状态点等基础组件的视觉与交互状态。
3. 统一导航与卡片图标、品牌标识、空状态与图表配色，使课堂演示画面更规整、可读。
4. 复核响应式、可访问性（对比度、焦点态、键盘可达）与打印样式。

## 三、已知视觉问题（只读核查结论）

以下条目基于基线代码与样式核查，实施前需在浏览器中逐页复核；不把推测当作已确认缺陷。

1. **设计令牌分散**：主色、中性色、边框色、文字色在 5 个 CSS 中重复硬编码；`static/js/` 内共检索到 69 处十六进制色值（`app.js` 39、`comments-analysis.js` 16、`quality.js` 6、`news.js` 4、`chart-export.js` 4），主要是 ECharts 色板、坐标轴文字与分割线颜色，与 CSS 令牌不联动。
2. **字号层级偏碎**：现有字号覆盖 8 / 9 / 10 / 11 / 12 / 13 / 14 / 15 / 16 / 18 / 22 / 23 / 24px 多档；表格与辅助文字多为 8–9px，课堂投影与远距离观看的可读性需要评估下限。
3. **图标体系不统一**：几何符号、箭头、加减号等 Unicode 字符混用，描边风格与尺寸不一致；导航展开箭头、卡片符号、状态点各写各的。
4. **语义状态色散落**：成功、警告、失败、信息色（绿 / 橙 / 红 / 蓝）在 `app.css`、质量页、新闻页、评论页与 JS 中分别硬编码，未形成统一的语义色阶；同一状态在不同页面的底色与文字色存在细微差异。
5. **组件样式跨文件重复**：筛选面板、表格卡片、按钮、徽章、输入控件的结构与样式在 `app.css`、`news.css`、`comments-analysis.css`、`ai-analysis.css` 中重复出现；调整一处视觉需要多点同步，容易遗漏。
6. **图表与页面配色脱节**：ECharts 色板（如 `#197b5b #59a984 #9dc8ae #e7b979 #8ba8cf`）、轴标签色、分割线色、空态文字色均在脚本内写死；图表导出 PNG 的配色也随之固定，令牌调整后图表不会自动跟随。
7. **层级与阴影偏弱**：卡片主要依靠 1px 边框区分层次，阴影仅用于 toast、筛选弹层与右下角导出按钮；页面整体偏平，卡片、弹层、浮层之间的层级关系不够明确。
8. **可访问性待核查**：焦点样式仅部分控件具备；文字与背景对比度未做过系统核查；表单控件的 `focus-visible`、键盘可达性与错误态提示需要逐页检查。当前无深色模式。
9. **响应式与表格滚动**：已有 1120px / 760px 两档适配；多张表格 `min-width` 在 1050–1650px 之间，窄屏依赖横向滚动，需要确认哪些表格允许滚动、哪些应改为卡片式排布。
10. **品牌与空状态资产缺失**：品牌标识为字母 `C` 色块；无 favicon；列表、图表、搜索无结果等空状态缺少统一的占位样式与提示规范。
11. **打印样式已有但需复核**：`app.css` 末尾有 `@media print` 规则，隐藏侧边栏与操作按钮；报告页与看板页打印效果需在实施阶段对照检查。

## 四、设计方向（建议，实施前确认）

1. **保持现有绿色主调与本地工具定位**：不引入重装饰、不改变产品气质；课堂演示可读性优先于视觉花样。
2. **令牌先行**：颜色、字号、间距、圆角、阴影、边框先收敛为 CSS 变量（必要时配套一份 JS 可读的图表主题配置），再替换组件样式。
3. **组件一次定义、多页复用**：基础控件样式集中在主样式表，页面样式只保留差异部分；避免跨文件复制同一段规则。
4. **线性图标体系**：导航与卡片图标改为统一网格、统一描边的内联 SVG；Unicode 字符仅保留状态点、箭头等无歧义场景。
5. **本地优先**：不加载联网字体、图标库或 CDN 资源；所有新增资源落在 `static/` 本地目录，与 README 中“本地页面无需加载远程脚本或字体”的约束一致。

## 五、设计令牌规划（草案）

实施阶段先在 `:root` 建立以下分组；具体色值在 S1 阶段对照基线截图确定，保证归一化后页面观感不发生意外偏移。

### 5.1 颜色

| 分组 | 令牌草案 | 用途 | 现状问题 |
| --- | --- | --- | --- |
| 主色阶 | `--color-primary-50 … 900` | 品牌绿、主按钮、链接、选中态 | 现有 `#187b5b`、`#10563f`、`#137552`、`#438f6c` 等近似绿值分散 |
| 中性色阶 | `--color-neutral-50 … 900` | 背景、卡片、边框、各级文字 | 灰绿文字色与边框色多档硬编码，缺少阶谱 |
| 语义色 | `--color-success / warning / danger / info` 及对应浅底 | 状态徽章、任务状态、质量等级、提示条 | 成功绿、警告橙、失败红、信息蓝在多文件重复定义 |
| 图表色板 | `--chart-1 … --chart-5` | ECharts 系列色、导出图配色 | 色板写死在 JS，与页面主色不联动 |

### 5.2 排版

| 令牌草案 | 用途 | 说明 |
| --- | --- | --- |
| `--text-xs / sm / base / lg / xl / 2xl / 3xl` | 辅助文字、表格、正文、卡片标题、页面标题 | 收敛现有碎字号；8–9px 仅保留给表格与脚注，并评估投影可读性下限 |
| 行高阶 | 正文、表格、标题 | 长正文与表格分别设行高 |
| 字体栈 | 沿用现有 Inter / 雅黑 / Noto Sans SC | 不引入远程字体 |

### 5.3 空间与形状

| 分组 | 令牌草案 | 用途 |
| --- | --- | --- |
| 间距 | `--space-1 … --space-8` | 卡片内边距、控件间距、栅格 gap |
| 圆角 | `--radius-sm / md / lg` | 小控件、卡片、弹层 |
| 阴影 | `--shadow-card / pop / fab` | 普通卡片、悬浮弹层、固定操作按钮 |

## 七、边界与保护规则

1. **只改展示层**：不修改路由、数据库、采集器、清洗规则、自然语言筛选规则与 AI 建议逻辑；模板中已有的后端变量名与数据字段保留。
2. **不删除既有资产**：旧页面、旧路由、历史数据、备份、研究材料与全部未跟踪文件继续保留；暂缓页面（评论分析、新闻、报告）只做视觉跟随，不恢复或移除入口。
3. **本地与隔离优先**：实施阶段使用现有 `_preview/` 隔离库与本地演示库核对画面；不向正式库写入未确认数据，不访问远程生产资产。
4. **提交纪律**：每个独立阶段完成后再暂存相关样式、模板、脚本与文档；分阶段提交 `main`，不推送；提交前运行现有测试与前端语法检查。
5. **本阶段暂缓项**：深色模式、品牌插画体系、远程字体 / 图标库、动效体系不在本轮范围；如后续需要，另立计划。
6. **不引入联网依赖**：新增图标、favicon 等一律本地存放；不修改 `static/vendor` 下 ECharts 发行文件与许可证。

## 八、决策点与本次采用取向

2026-11-24 实施时按以下默认取向执行；如需调整，另立改动：

1. **整体风格**：维持现有绿色扁平基调，普通卡片加极淡阴影，弹层 / 浮层使用更强阴影；字号下限暂保留现状，不做投影字号强制下调。

3. **品牌资产**：保留字母 C 色块 brand mark；补本地 SVG favicon，不设计正式 logo 与插画。
4. **图表色板**：沿用绿—橙—蓝—红—紫—浅绿 6 色板，集中到 `static/js/theme.js`；语义色不进入图表系列。
